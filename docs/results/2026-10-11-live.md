# Live verification, 2026-10-11

A small check that the standalone engine runs end to end against a real provider. It is a smoke
run, not a benchmark: one dataset, a 40-example train stream, 20 search and 20 test examples, 3
iterations. **These numbers can't be compared with the paper's Table 2.** The sample is tiny, the
models differ and nothing was repeated. A single example is worth 5 accuracy points.

## Providers

The engine tries providers in this order: unikey, then groq, then openai.

| Provider | Result |
|---|---|
| unikey | `models` listed the catalogue; `chat` failed with `HTTP 403 insufficient_user_quota` (the account has no credits) |
| groq | `models` and `chat` both failed with `HTTP 403: error code: 1010`. This is a Cloudflare block on the default `Python-urllib` User-Agent: the same request with a custom User-Agent got through to the API (it then returned 404 for `llama-3.3-70b-versatile`). Not fixed here; it needs a User-Agent header in `meta_harness/providers.py` |
| openai | worked |

- Base (harness) model: `gpt-4o-mini`
- Proposer model: `gpt-4.1-mini`
- Recorded tool-call fixture: `gpt-4.1` (response `model` = `gpt-4.1-2025-04-14`), saved to
  `tests/fixtures/providers/live_tool_calls.json`. `parse_openai` read it as one `list` call with
  no changes, so the parser needed no fix.
- Prices passed to the run (USD per 1M tokens, input/output/cache-read): gpt-4o-mini 0.15/0.60/0.075,
  gpt-4.1-mini 0.40/1.60/0.10.

## Data

`python -m meta_harness fetch symptom2disease` (the default capped sample: 160 train, 40 val, 200
test). I subsampled it with seed 0 (`random.Random(0).shuffle`, then took the first N) into
`.meta-harness-data/s2d-small/`: 40 train, 20 val (the search split) and 20 test.

## Command (Meta-Harness optimizer)

```bash
python -m meta_harness --env-file <repo>/.env search \
  --harness baselines/classification/zero_shot.py --harness baselines/classification/few_shot.py \
  --train .meta-harness-data/s2d-small/train.jsonl --search .meta-harness-data/s2d-small/val.jsonl \
  --test .meta-harness-data/s2d-small/test.jsonl --protocol online \
  --domain classification --metric accuracy \
  --provider openai --model gpt-4o-mini --proposer-provider openai --proposer-model gpt-4.1-mini \
  --iterations 3 --candidates 2 --max-evaluations 8 --max-tool-calls 20 --isolation process \
  --price openai:gpt-4o-mini=0.15,0.60,0.075 --price openai:gpt-4.1-mini=0.40,1.60,0.10 \
  --root .meta-harness-live-s2d
```

## Step 5: Best-of-N with the same budget

I ran the same command with `--optimizer best-of-n --root .meta-harness-live-s2d-bon`.

| | Meta-Harness | Best-of-N |
|---|---|---|
| valid candidates proposed | 4 | 0 |
| best search acc | 0.80 | 0.75 (seed) |
| best test acc | 0.55 | 0.55 (seed) |
| harness evaluations | 6 | 2 (seeds only) |
| billed cost | $0.336 | $0.087 |

Best-of-N wrote no candidate in any of its 3 iterations. Each ended with
`ProposerBudgetExceeded('no candidate after 20 tool turns')`: the proposer spent its 20 tool calls
paging through `run.json` and never wrote a file. So this comparison only shows that the proposer
with the Best-of-N view didn't reach a write within the 20-call cap I set. It says nothing about
which optimizer is better. A fair comparison needs the default tool-call cap and more than one seed.
